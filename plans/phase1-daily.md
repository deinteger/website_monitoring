# 1단계 — 매일 페이지 전수점검과 결과서

이 단계의 목표는 **자동 배치 실행**과 **HTML 웹 대시보드의 수동 실행**이 동일한
`DailyPipeline`을 사용하여 페이지를 점검하고, 동일한 JSON 상태·캐시·이슈 이력과
XLSX·스크린샷 결과를 생성하도록 완성하는 것이다.

작업자는 `docs/requirements.md`를 공통으로 읽고, 현재 작업에 해당하는 문서만 추가로
읽는다. 전체 테스트 수와 최근 검증 결과는 고정 숫자로 중복 기록하지 않고 최신
`HANDOVER.md`를 기준으로 확인한다.

## 공통 운영 원칙

- 별도 SQL DB 없이 JSON·JSONL 파일로 상태와 실행이력을 관리한다.
- 자동 배치와 웹 수동 실행은 별도 점검기를 만들지 않고 같은 `DailyPipeline`을 호출한다.
- 실행 방식이 달라도 URL 정규화, 점검 규칙, 캐시, 이슈 생명주기와 결과 형식은 동일하다.
- 동시에 두 점검이 실행되지 않도록 공통 실행 잠금을 사용한다.
- 기본 안전값은 HTTPS, 동시요청 1, 요청 간격 1초 이상, 최대 10 URL로 유지한다.
- 실제 사이트 검증 없이 최대 URL 수를 임의로 확대하지 않는다.
- 이미지·자료 출처, 표 제목셀, 비표준 플러그인, `robots.txt`는 초기 점검에서 제외한다.
- 작업 완료 시 `PLAN.md`, `HANDOVER.md`와 인수인계 보관본을 갱신한다.

## 1단계 최종 완료 기준

- 자동 배치와 HTML 웹 수동 실행이 동일한 `DailyPipeline`을 사용한다.
- 두 실행 방식의 JSON·캐시·이슈 생명주기·XLSX 결과가 동일한 기준으로 생성된다.
- 매일 자동점검과 사용자가 요청한 수동점검을 모두 수행할 수 있다.
- 웹 대시보드에서 최신·과거 결과, 진행상태, 오류 근거와 스크린샷을 확인할 수 있다.
- 공통 실행 잠금으로 동시 실행과 상태파일 충돌을 방지한다.
- 실제 대상 사이트 전체 점검의 서버 부하·실행시간·실패율을 검증했다.
- 최신 전체 테스트가 통과하고 운영방법과 미해결 사항이 `HANDOVER.md`에 기록돼 있다.
