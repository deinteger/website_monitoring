# 인수인계 작성 규칙

## 목적

서로 다른 Codex 계정과 세션이 같은 프로젝트를 이어서 작업하더라도 현재 상태를
추측하지 않고 즉시 확인할 수 있게 한다.

## 작업 시작

1. `AGENTS.md`, `PLAN.md`, `HANDOVER.md`를 읽는다.
2. `PLAN.md`가 가리키는 단계 파일에서 현재 항목만 읽는다.
3. `AGENTS.md`의 문서표에 따라 현재 작업용 세부 문서만 읽는다.
4. 인수인계에 적힌 변경 파일과 테스트 결과를 직접 확인한다.
5. 작업트리의 기존 변경을 임의로 삭제하지 않는다.
6. 현재 단계 파일의 첫 미완료 항목을 작업한다.

전체 `docs/`, 다른 단계 계획, PDF·HWPX 원본을 매 작업마다 읽지 않는다.

## 작업 종료

현재 단계 파일과 `PLAN.md`를 갱신한 뒤 `HANDOVER.md`를 아래 형식으로 전면 갱신한다.

```markdown
# HANDOVER.md

## 현재 상태
- 작업일시:
- 현재 단계:
- 전체 상태: 완료/부분완료/실패/차단

## 이번 작업에서 완료한 내용
-

## 변경한 파일
- 파일: 변경 이유

## 실행 및 검증 결과
- 명령:
- 결과:
- 실제 외부 요청 수:

## 미완료·실패·알려진 문제
-

## 유지해야 할 결정사항
-

## 다음 작업자의 첫 작업
- 하나의 구체적인 작업
- 시작 파일 또는 명령
- 완료 조건
```

그 후 같은 내용을 `handover/archive/YYYYMMDD-HHMM.md`로 저장한다.

## 금지사항

- `완료`라는 말만 남기고 테스트 결과를 생략하지 않는다.
- 다음 작업을 `나머지 개발`처럼 모호하게 쓰지 않는다.
- 비밀번호·API 키·개인정보 원문을 인수인계에 남기지 않는다.
- 실패 사실이나 임시 우회코드를 숨기지 않는다.
- 다음 작업자가 재현할 수 없는 임시 경로만 남기지 않는다.
