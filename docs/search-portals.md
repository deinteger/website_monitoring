# 검색포털 점검 원칙

## 목적

Google·Naver·Daum 검색결과에 남아 있는 접속불가 또는 잘못된 URL을 발견하고
조치상태를 관리한다.

## 처리 우선순위

1. 기존에 확보한 오류 URL seed를 매일 재검증
2. 공식 API 또는 허용된 방식으로 신규 검색결과 수집
3. 자동수집이 불가능하면 CSV 수동입력 지원
4. 수집 URL을 실제 HTTP 요청으로 재검증

## 제한사항

- 검색결과는 전체 색인 목록이 아니다.
- 결과 순위와 노출 URL은 시점·사용자·포털 정책에 따라 달라질 수 있다.
- 캡차 발생 시 자동해제·무한재시도·우회를 금지한다.
- 수집 실패는 오류 URL 0건으로 처리하지 않는다.
- 포털별 `수집 성공`, `부분 수집`, `수집 실패`, `수동입력` 상태를 기록한다.
- 마지막 신규수집일과 마지막 URL 재검증일을 구분한다.

## Google 주의사항

Google Custom Search JSON API는 신규 사용과 서비스 지속성에 제약이 있으므로 필수
전제로 하드코딩하지 않는다. provider 인터페이스로 분리하고 수동 seed 입력을 항상
지원한다.

## 일일 운영

- seed와 이전에 발견한 URL의 현재 상태는 매일 점검한다.
- 신규 검색결과 수집은 설정된 주기로 시도한다.
- 신규수집이 실패해도 기존 URL 재검증과 결과서 생성은 계속한다.
